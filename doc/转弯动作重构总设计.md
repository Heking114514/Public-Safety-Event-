# 转弯动作重构总设计

记录日期：2026-10-10（北京时间）  
状态：待 agent 按任务书实现，尚未替换生产接口。

## 目标

将一次路口转弯建模为一个独立动作。动作从入口上下文创建，到成功、需要重规划或故障保持结束；期间不允许 `waypoint_navigator`、`corner_shunt`、障碍恢复和任务管理器同时修改转弯内部状态。

## 唯一拥有者

现有 `TurnManeuverController` 作为唯一转弯动作拥有者，后续只做职责收敛，不再新增第二套转弯状态机。

### `visual_navigation` 负责

- 接收路线航点并判定何时需要停车转弯；
- 创建一次不可变 `TurnRequest`；
- 每个控制周期提供当前位姿、速度、IMU 和输入健康状态；
- 发布动作控制器返回的速度命令；
- 根据 `TurnResult` 继续路线、请求恢复规划或保持故障。

### `TurnManeuverController` 负责

- 保存 `geometry_heading`、`arrival_heading`、`target_heading`、路口位置、车体参数；
- 入口安全检查和必要的前后微调；
- 前进圆弧和出口对齐；
- 预测轨迹、footprint 和道路包络检查；
- 判断动作是否有实际进展；
- 输出唯一终态：`COMPLETED`、`NEED_REPLAN` 或 `FAULT`。

### `corner_shunt` 负责

- 局部坐标变换；
- 候选动作和预测姿态计算；
- 几何安全检查；
- 对当前输入给出控制量。

它不负责路线推进、任务顺序、障碍恢复或重规划，不直接改变导航器状态。

### `new_map_planner` 负责

- 根据地图、目标和起点模式生成路线；
- 验证道路、footprint 和静态/动态障碍几何可行性；
- 对恢复请求生成受限的退离路线；
- 返回结构化失败原因。

它不执行转弯控制，不读取控制器内部 trim 状态，也不根据单次控制周期决定是否急停。

## 动作接口口径

### `TurnRequest`

至少包含：

- `junction_id`；
- `junction_x/y`；
- `geometry_heading`：道路入口几何方向；
- `arrival_heading`：刹停时车辆实际航向；
- `target_heading`：出口道路方向；
- `reverse_arrival`；
- 车体长宽、轴心偏移和道路宽度；
- 当前实测 pose。

这些字段在动作启动时冻结。后续定位更新只更新 `current_pose`，不改变道路几何语义。

### `TurnResult`

```text
RUNNING       继续输出动作命令
COMPLETED     动作完成，交回路线跟踪
NEED_REPLAN   动作无法继续，携带最后安全 pose 和失败原因
FAULT         无法确认安全，零速并保持任务
```

`TURN_REPLAN` 不再作为内部循环状态；它是 `NEED_REPLAN` 的上层处理结果。

## 状态边界

动作内部可以保留入口检查、微调、圆弧和出口对齐等阶段，但这些阶段只能由动作控制器迁移：

```text
IDLE
  -> ENTRY_CHECK
  -> TRIM / ARC / EXIT_ALIGN
  -> COMPLETED
  -> NEED_REPLAN
  -> FAULT
```

上层导航器不能在 `TRIM` 和 `ARC` 之间插入自己的重规划分支。障碍恢复只有在动作返回终态后才能接管。

## 失败处理

1. 当前预测命令被拒绝，但实测 pose 仍安全且误差改善：继续动作。
2. 当前预测命令被拒绝，重复输入没有改善：停止重复 trim，返回 `NEED_REPLAN`。
3. 实测 pose 已离开安全包络或无法确认：返回 `FAULT`，零速保持。
4. `NEED_REPLAN` 携带最后安全 pose、路口 ID、入口车道和失败原因；规划器据此选择恢复模式。

## 验证顺序

1. 用隔离核心回放正常居中、提前 2 cm、入口航向残差、首次弧线拒绝和恢复后再次转弯。
2. 验证动作控制器不会重复发送无改善的被拒命令。
3. 验证 `TurnResult` 到导航器/规划器的单向接管关系。
4. 通过契约测试后，再替换生产接口；不同时修改 Z 轴协议、全局搜索和底盘速度策略。
