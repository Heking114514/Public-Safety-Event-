当前实际执行链：

```text
前方信号 -> 分类为异常 -> BeginPoseRecovery（重置当前转弯）
  -> braking -> candidates -> 总控评估 -> SelectRecovery
  -> plan 固定生成 RETREAT / ALIGN / TURN 三步
  -> 实时倒车到 anchor 节点附近 -> 换向停止等待
  -> ALIGN 直接启动唯一固定转弯控制器
  -> CAPTURE -> APPROACH_ENTRY -> TURN_60 -> DIAGONAL_CREEP -> TURN_30
  -> 控制器返回 COMPLETED 后跳过剩余 steps -> 停车 -> complete
  -> 总控用报告 pose 正式规划 -> WAIT_ROUTE_ACK -> EXECUTING
```

固定动作完成、后续正式规划和 ACK 是不同时间点。当前复跑在严格转弯扫掠处终止，没有走到 complete。

## 7. 冻结范围、参数和物理来源（§1、§9）

本轮核对未修改业务和参数。对“此前实现没有改过其他包/正常参数”的历史声明，只能根据可核查基线作有限判断：

| 冻结要求 | 当前可核查事实 |
|---|---|
| 只改 Contrast，不改生产包、总控、接口、simulator | 相对 HEAD，这些包都有已有工作树改动。不能据此认定是哪轮引入，也不能直接重复“这些包从未改写”。 |
| Contrast 正常参数不变 | 相对 HEAD，正常 angular 从 0.65 到 0.35、min angular 从 0.50 到 0.15、creep 从 0.035 到 0.030。可能是用户已有调参；未作归因，也未还原。 |

| 正常动作不被恢复逻辑掩盖 | 固定动作确被复用；当前动作测试失败未通过调参处理。本轮没有放宽任何正常门槛。 |

补充两项执行可靠性差异：

1. [恢复:155](../src/contrast_navigation_core/src/pose_recovery_control.cpp#L155)、174、181、314、325 的停车仅用缓存轮速和时间，不用已有 telemetry 新鲜度/连续停止样本；部分等待在阶段超时之前返回，可能无限等停车。
2. 暂停/定位无效会在上层发布零速；但 motion hold 的 [runtime:280](../src/contrast_navigation_core/src/runtime.cpp#L280)、298 会 ResetManeuver，清除转弯控制器，却不清 `recoveryTurnManeuverStarted_`。继续恢复时可能向 inactive 控制器 update 并故障；这是源码路径风险，本轮没有执行中暂停场景验证。不能把 pause_clock 当成已验证可无损续转。
