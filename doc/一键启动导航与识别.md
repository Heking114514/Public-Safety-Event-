# 一键启动导航与识别

在本机桌面终端执行：

```bash
cd /home/hjh/zhongzhouyanda/Public-Safety-Event-
./scripts/start_mission.sh
```

脚本先检查模型和图库，再依次打开 `insight_cup`、`final_navigation`、`planner` 三个终端。识别程序自动打开浏览器，规划脚本打开任务操作台。导航入口维持原有增量构建和录包流程，规划入口也维持原有构建流程。

识别使用 `build/insight_cup/insight-cup`，需先通过 `colcon build --packages-select insight_cup` 构建。识别固定使用 CPU、关闭障碍识别，并订阅 `/camera/camera/color/image_raw`；只有导航的 RealSense 节点打开 D455，不会双重占用 USB 相机。三个窗口使用 `config/navigation_startup.yaml` 中相同的 ROS domain 和 RMW 设置。

检测到 `new_map_planner_ui` 节点后倒计时 5 秒；此节点表示规划操作台正在初始化，不是桌面窗口绘制完成的逐帧检测。倒计时结束后继续等待任务总控进入 `IDLE`，且识别实际处理过相机画面，再调用 `/navigation_mission/control` 的 `START`。任务点读取任务总控已有配置，执行完整三阶段巡视；总控负责规划、路线确认和控制器激活。不会使用固定 CSV，也不直接发布速度。

延迟、等待上限、窗口间隔、图像话题和识别端口在 `config/mission_startup.yaml` 中配置。默认等待上限为 300 秒。窗口退出、人工启动或暂停任务、启动被拒绝或服务响应超时都会取消自动启动；不会反复重发 START。关闭规划窗口只会取消尚未发送的自动启动，不会停止已经接受的任务。

## 仅检查与查看命令

```bash
./scripts/start_mission.sh --check
./scripts/start_mission.sh --dry-run
```

这两个选项不会打开窗口或发送任务。缺少模型和图库时，检查会打印完整路径，并在打开窗口前退出。需从原机器补齐以下文件，保持 `src/insight_cup/` 下相对路径不变：

- `models/yolo/best.onnx`
- `models/face/models/face_only_r50/det_10g.onnx`
- `models/face/models/face_only_r50/w600k_r50.onnx`
- `models/knife/pplcnetv2_base_knife10/inference.onnx`
- `data/face_gallery/cpp/trainv5_gallery_r50.icg`

## 中止任务

在已加载工作空间环境并设置相同 `ROS_DOMAIN_ID` 的终端执行：

```bash
ros2 service call /navigation_mission/control \
  mission_control_interfaces/srv/ControlMission \
  '{command: 4, target_ids: []}'
```

不要通过关闭 GUI 来代替停止任务。车辆接受启动后由任务总控独立运行。
