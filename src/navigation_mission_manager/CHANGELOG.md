# Changelog

## Unreleased

- 2026-10-15 修复 Contrast 转弯失败后总控等待不会发布的安全锚点：总控显式请求现有路线回退服务，控制器停稳后沿已执行轨迹回放，完成后再普通重规划；无轨迹、服务拒绝/响应超时和回放无进展均明确结束。保持转弯参数及 1.5 秒无进展阈值不变。

- RFID 读卡先申请驻停，停车确认后再校验卡号、任务和路线；空闲、暂停或路线未 ACK 时也不再丢弃停车请求。任务或路线未就绪时保持故障驻停，避免任务管理器重启后旧导航路线继续执行；增加节点级驻停和校验顺序回归测试。

- 增加总控内部 `blocked_lane_ids` 完整快照和单调 `obstacle_revision`：动态障碍确认时依据当前路线道路归属更新快照，过期清除时同步递增版本。
- 规划请求保留原有动态障碍多边形，并在规划器消息字段存在时兼容填充阻塞道路快照；路线激活前兼容校验规划结果使用的障碍版本和道路集合。当前规划器消息尚无这些字段，待其加入后自动启用响应校验。

- RFID 播报后的驻停时长调整为 `1 s`，巡线速度保持现有 `0.05 m/s`。

- RFID 播报现在使用下位机上报的卡号；地图任务号和内部超节点名称仅用于路线确认，不再作为播报编号。

- 2026-10-11：路口动作无安全解后改由控制器沿已执行的安全轨迹闭环回放；总控不再把转弯
  中途安全姿态交给规划器生成直线 `TURN_RECOVERY` 路线，回放完成后才恢复普通规划。

- 路口动作报告 `TURN_NEED_REPLAN` 后不再使用可能越界的当前融合位姿直接重规划；总控清除旧路线并进入故障驻停，等待控制器提供明确的安全恢复姿态，避免反复返回 `START_POSE_COLLISION`。

- 增加规划请求和服务失败日志，记录当前融合位姿、路线规模、动态障碍、重规划/恢复状态、失败状态和重试次数，便于串联总控、规划器与控制器原因。

- `/safe` 适配改为总控内部记录地图障碍后再向控制器转发，避免总控订阅自身输出形成障碍回环。
- 识别目标播报复用串口语音 service 但不新增总控驻停，保留识别模块自身的 `inspection` 驻停申请。
- 总控直接接入 `/insight` 和 `/safe`：按目标顺序排队人物/刀具播报，并把视觉障碍距离投影为地图障碍，复用现有避障入口；无视觉发布者时不改变原有业务。

## 0.4.1 - 2026-10-09

- 接入导航器的 `TURN_NEED_REPLAN` 状态。路口动作无安全解时，总控从最新融合位姿重新规划
  当前阶段，保留动态障碍记忆且不调用障碍倒退恢复，避免把几何动作失败误报为障碍。

## 0.4.0 - 2026-10-08

- 把 RFID 从“卡号映射任务点”改为“路线预期超节点 + 固定物理点位”。读卡事件绑定
  当前路线中的 `s1`–`s12`，里程计不能单独确认或推进节点。
- 增加 RFID 停车、融合位置校正及收敛等待、播报/1 秒停留、指定航点放行的串行状态流程；
  校正或放行失败时保持故障驻停。
- 将完成路线后的几何衔接倒退与真实障碍恢复解耦；无动态障碍时调用独立路线衔接服务，
  总控保持 `REPLANNING`，不再进入 `RECOVERING_OBSTACLE`。

## 0.3.0 - 2026-10-08

- 将任务总控、三阶段任务模型、障碍记忆、事件播报、RFID 修正/语音状态机、驻停代理和
  测试播报器从 Python 全量迁移到模块化 C++17，保持原可执行文件名和 ROS 接口。
- 包构建类型由 `ament_python` 改为 `ament_cmake`，核心逻辑改用 GTest；loopback 已验证
  路线 ACK、阶段任务提交、下一段规划以及外部驻停申请/释放。

## 0.2.1 - 2026-10-08

- 增加任务管理器启动就绪日志和状态迁移日志，展示地图文件、自动启动配置、任务点数量
  以及完整状态链路；日志使用 `rclpy` 接受的单字符串格式，避免节点初始化异常。

## 0.2.0

- 收回 RFID 任务流程：实际读卡确认任务点、统一驻停计时、编辑播报文本、调用串口语音
  service，并在 3 秒后恢复车辆；规划路线不再直接确认 RFID 任务完成。
- 增加 `/navigation_mission/speech_text` 上行接口，其他节点可委托总控驻停并通过串口播报文本。
- RFID 驻停期间由总控调用融合节点的位置校正 service；导航就绪不再依赖串口播报
  service，loopback 仿真可在无串口节点时启动。
- 增加 `/navigation_mission/set_motion_hold` 和
  `/navigation_mission/continue_obstacle_retreat` 总控入口，外部节点不再需要直接
  调用导航器底层驻停与倒退服务。
- 增加任务点确认模式：实车默认使用真实 RFID，loopback 在路线实际完成后使用
  `visit_order`，避免仿真因没有串口读卡器而重复同一目标。
- `new_map_planner` UI 与 `route_editor` 的驻停请求改走总控公开服务，并按总控转发后的
  来源名称判断各自驻停所有权。

## 0.1.3 - 2026-10-07

- 将已确认路线的连续普通路口计数带入下一次规划请求，让图搜索在阶段接力时延续约束。

## 0.1.2 - 2026-10-07

- 阶段交接规划若没有新增当前阶段任务/道路进度，不再下发厘米级空转路线；任务节点会
  请求控制器沿刚完成路线有界后退，再从更早路口规划下一阶段。
- 动态障碍增加 120 秒默认保留时间；近期重规划保持封路，长时间未再次观测则释放，
  若障碍仍在会由感知重新触发，避免临时障碍永久阻断最终道路覆盖。

## 0.1.1 - 2026-10-06

- 规划器明确返回当前姿态无路后，任务状态机请求控制器继续退到更早历史锚点；仅在
  控制器再次报告 `OBSTACLE_REPLAN_REQUIRED` 后重规划，并覆盖轨迹耗尽、倒车故障和
  后续规划成功的状态回归测试。
- 控制器在产生任何运动前拒绝新路线时直接进入可诊断故障，不再把同一条不可执行路线
  以约 0.4 秒周期无限重规划和重复下发。

## 0.1.0 - 2026-10-05

- 新增正式自主任务状态机，统一管理三阶段规划、路线 ACK、进度提交和故障驻停。
- 新增动态障碍记录及 `OBSTACLE_REPLAN_REQUIRED` 自动重规划链。
- 当前恢复锚点规划无路时，通过控制器服务按实际历史轨迹分段继续倒退并再次规划；
  默认每段 `0.40 m`、最多 4 次，轨迹耗尽或超限后驻停报错。
- 新增事件候选去重、停车播报和播报 ACK 编排接口。
