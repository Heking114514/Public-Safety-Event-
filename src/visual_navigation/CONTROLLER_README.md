# 导航控制器基线与方向

## 文档目的

本文档记录 `visual_navigation` 控制器的可追溯基线、当前已知问题和后续设计方向。
它用于决定控制器改动是否属于同一条技术路线，避免把临时实验结果当成稳定版本。

## 当前基线

本控制器文档采用 **2026-10-09 02:30（中国标准时间）的运行版本** 作为基线。
这是当时实际用于测试和判断控制器行为的版本，不把更早的 Git 提交直接等同为运行基线。

该运行基线包含：

- `waypoint_navigator` 作为路线执行器；全局路线由外部规划器发布。
- 路径跟踪使用融合位姿、航向误差、横向误差和角速度反馈。
- 需要停车的路口经过 `TURN_STOP`、`TURN_CHECK` 后进入局部转弯控制。
- 车体 footprint 在局部转弯控制中进行安全检查。
- 障碍恢复沿已记录轨迹退回语义锚点，再等待任务层重新规划。
- RFID 到点流程由任务总控驻停、确认和位置校正，控制器不拥有 RFID 任务决策。

这个时间点没有对应的独立 Git 提交标签，基线应由运行时间、参数快照、rosbag 和源码
状态共同确定。`78fcf79`（`before change the fused odom`）只作为代码历史参考，不能替代
02:30 运行基线。

当前工作树存在未提交修改，不能自动视为新的稳定基线。任何新控制策略都必须先在独立
实验分支或临时副本中验证，再决定是否进入生产控制器。

## 控制边界

控制器包只负责以下内容：

- 接收路线并按航点执行；
- 根据实时融合位姿输出 `/cmd_vel_nav`；
- 执行已标记路口的局部转弯；
- 执行障碍停车和历史轨迹恢复；
- 发布导航状态、路线确认和驻停状态。

以下内容不由本包决定：

- 全局道路选择、任务顺序和障碍绕行路线；
- RFID 卡号到任务点的映射；
- `map -> odom` 的 RFID XY 校正；
- 相机障碍识别和仿真器真值；
- 车体物理尺寸的独立定义。

## 已确认问题

### 路口转弯

最近 rosbag 显示，车辆在 RFID 路口可能带着数度航向残差进入下一段转弯。RFID 校正只改
融合位置 XY，不改 yaw。道路入口方向和车辆实际到达 yaw 必须分别使用。

转弯不能依赖单一固定弧线，也不能用原地旋转掩盖入口姿态错误。车体 footprint 必须在
每个候选动作和预测窗口内检查。

### 速度死区

电机有效直行速度范围是 `0.035~0.12 m/s`。普通直行、路口前进和路口倒车动作不能因为
加速度限幅先后发布低于 `0.035 m/s` 的非零速度。停车、RFID 扫描和航向稳定阶段可以有
独立的低速或零速协议，不能混用普通直行速度规则。

### 障碍恢复

恢复目标必须位于车辆可倒退方向。目标落在车头前方时，控制器不能发布 `vx=0` 配合角速度
原地旋转；应停车并请求任务层继续回退到更早的语义锚点。倒车只允许沿已执行轨迹，并且
不能跨越道路中间的非语义位置。

## 后续方向

### 路口状态格

普通路口和 RFID 路线起点路口统一使用经过车体扫掠验证的局部状态格。动作集合只允许：

- 前进弧线；
- 路口内倒车弧线；
- 必要的停顿和重新规划。

动作集合不包含原地旋转。倒车只在已经确认的路口开放，普通道路跟踪不触发路口倒车。
控制器和 `new_map_planner` 必须共享同一套车体尺寸、轮轴偏移、道路宽度和安全余量。

### RFID 接近

距离 RFID 超节点 `0.20 m` 时进入低速接近，直行 `vx=0.035 m/s`；到达扫描窗口后由任务
总控驻停、确认和校正。控制器不因里程计先到就跳过 RFID，也不在 RFID 校正时修改 yaw。

### 障碍恢复

障碍恢复按以下顺序工作：

```text
发现障碍 -> 停车确认 -> 沿历史轨迹倒退 -> 到达语义锚点 -> 停车校正 -> 请求重规划
```

如果当前位置无法生成后向可行目标，立即停止并请求更早锚点；不能以原地旋转代替倒退。

## 验收条件

控制器改动至少需要覆盖：

- 第二个 RFID 路口带航向残差的入口；
- 左右转和入口横向偏差；
- `vx=0.035 m/s` 下的车体扫掠；
- 路口前进/倒车组合不包含原地旋转；
- 障碍恢复目标在车头前方时的停车和继续回退；
- RFID 接近阶段的速度上限和停车交接。

只有单元测试、规划器扫掠验证和独立 loopback 关键链路都通过后，才能把实验态标记为新的
控制器基线。

## 使用规则

- 修改前先更新本文档中的基线或问题记录；
- 控制器、规划器、融合和仿真器分开验证；
- 不用参数放宽道路边界来掩盖控制失败；
- 每轮编译和仿真结束后清理自己启动的进程；
- 所有结论必须能由测试、日志或 rosbag 重现。
