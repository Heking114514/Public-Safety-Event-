# CPU 优化实测与验收状态

日期：2026-09-24。硬指标是相同输入和定位质量下，整个 SLAM 进程 CPU
至少降低 20%；内存仅辅助记录。当前尚未通过车上红外双目 SLAM 的验收。

## 数据与测试口径

固定 bag：`/media/hjh/E1/rosbag_recording/navigation_runs/20260923T135935.356089Z_39a8ddbcb33a/bag`。
已审计 metadata、解压的 SQLite、CameraInfo、诊断和运行清单。这包录制的是
640×480 RGB8（2431 帧，约 15 Hz），实际车上 SLAM 输入是 848×480×15 红外双目，
800 特征、6 层、CLAHE 开启、IMU 融合关闭。左右红外图像没有被录入。

所以全流程试跑使用 RGB **单目**，公共提取/匹配模块可验证，双目匹配和车上
定位质量不能由此验收。采用 bag 的真实 RGB 标定，含 k3，保留全部原始像素和
帧，按全部原始时间戳回放。相机 fps=15，800 特征、6 层。禁用 viewer。

CPU 用 CLOCK_PROCESS_CPUTIME_ID 汇总整个进程全部线程；词典加载、RGB 原始文件
读入/预驻留在计时前，末帧之后等建图/回环队列完成并确认线程结束再停表。
模块用调用线程的 CPU 时钟，包含/独占时间分开记录。OpenCV 池内其他线程
计入进程 CPU，但不计入调用线程的模块数值。不同版本串行运行。

机器：Intel i5-13500H，x86_64，GCC 11.4，OpenCV 4.5.4，Release/O3/march=native。
这不是 RK3588 实测。动态计时探针有开销，完整回放每组目前只有一次；数字为
探索性结果，不是稳定收益保证。早期抽样并行试跑的百分比已作废。

## 已测代码候选

候选源码已保存在 ORB_SLAM3 子仓库分支 `perf/exact-cpu-candidates-20260924`，
提交 `4dce753`，独立目录 `/media/hjh/E1/orbslam3_optimization/candidate`。
主目录子仓库仍为 `d803877`。候选包含：

- 原先的网格引用和描述子中位数精确选择。
- ORB 提取：移动八叉树节点数据、复用 FAST 临时数组、保持边界的高斯滤波、
  直接写入最终描述子行，以及旋转采样的 SIMD/半整数边界标量回退。
- ORB 匹配：20 处仅用于距离比较的 `.row()` 临时矩阵改为行指针。
  保留原位计数定义、候选遍历顺序、阈值、ratio test 和 MapPoint 锁/clone。

距离内核从 8×32 位 POPCNT 换为 4×64 位的另一候选没有稳定收益，未纳入。

## 公共模块严格验证

- 提取器 6 层：全部 2431 帧 + 边界样例，共 2993 用例、1,988,159 个关键点。
- 提取器 8 层：2993 用例、2,014,458 个关键点。
- 每个关键点的全部字段、顺序、所有描述子字节、金字塔像素和重叠区分区完全一致。
- 346,336 个角度/半整数采样边界验证通过；默认舍入模式，不启用 fast-math。
- 原版 16 线程 vs 原版 1 线程、原版 16 线程 vs 候选 1 线程，同样各 2993
  用例逐位一致；包括 RGB 转灰度。该验证覆盖提取器，不覆盖所有 OpenCV 算子。
- 1920 组初始化/两种 BoW 匹配场景输出完全一致，包含平局、重复描述子、
  ratio/阈值边界和非对齐矩阵行；并非全部 Fuse/鱼眼路径的系统回归。

独立进程、固定核心、全部 2431 帧、预热后 CPU 微基准：保守提取优化下降
5.43%，含 SIMD 的版本下降 8.24%。这是 **提取器模块** 的收益。

## 线程调度控制组

仅将 OpenCV 工作者从默认 16 改为 1，保留 Tracking/Mapping/LoopClosing 的
SLAM 线程及全部算法参数。此为独立调度实验，不合并进纯代码收益百分比。

| 版本 | OpenCV 线程 | CPU 秒 | OK 帧 |
| --- | ---: | ---: | ---: |
| 原版 | 16 | 132.5049 | 1077 |
| 组合 | 16 | 115.2824 | 1077 |
| 原版 | 1 | 85.3378 | 1369 |
| 组合 | 1 | 86.6851 | 1380 |

原版 1 线程相对原版 16 线程少 35.60% CPU，但重新初始化和地图数量发生变化，
不能直接当作“同效果下降 35.6%”验收结果。同为 1 线程时，组合相对原版反而
增加 1.58% CPU，逐帧状态相差 15 帧。两个共同有效轨迹片段的 Sim3 对齐差异
也不同，第二段旋转 RMSE 约 24.31°，不支持效果等价结论。这四次不同调度下
的运行说明，需要重复基线估计波动、控制工作量并取得实际双目数据后再决定
正式替换；不能只挑其中 CPU 下降的一组报告成功。
